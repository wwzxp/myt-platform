# UI 信息架构（提议）

- 状态：提案，待确认
- 依据：旧项目三个标签页的实际控件清单（`docs/spec/legacy/*`）+ `docs/reference/wechat-data-analysis-desktop.md` 的界面组织方式
- 目标：把旧项目里 8 个对话框、3 套设备树、4 份重复按钮栏，收敛为「一屏一职责」的 Web 界面

## 1. 全局框架

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：授权状态 · 宿主在线 N/M · 运行中任务 K · 告警 · 用户     │
├─────────┬────────────────────────────────────────────────────┤
│ 左侧窄轨 │ 主内容区（路由）                                    │
│ 设备     │                                                    │
│ 任务     │                                                    │
│ 账号     │                                                    │
│ 素材     │                                                    │
│ 设置     │                                                    │
└─────────┴────────────────────────────────────────────────────┘
```

窄轨导航 + 单列宽内容，与 WDA 的组织一致。不做多标签页套多标签页。

## 2. 页面清单

| 路由 | 页面 | 解决的问题（旧项目对应物） |
|---|---|---|
| `/devices` | 设备农场 | `XhsDeviceTab` 设备树 ×3 份副本、`ConnectDeviceDialog` |
| `/devices/:id` | 设备详情（抽屉） | 设备行「设置」、单设备状态散落 |
| `/tasks` | 任务中心 | 三套「任务配置 + 开始任务 + 取消 + 查看日志」按钮栏 |
| `/tasks/new` | 新建任务向导 | `LoginModeDialog`、`NotePublishConfigDialog`、`TaskConfigDialog` |
| `/tasks/:id` | 运行详情 | `LogViewerDialog`、进度行、事件流 |
| `/accounts` | 账号库 | `AccountImportDialog` 的 8 个子页 |
| `/assets` | 素材库 | 头像/昵称/图片/文案的散装 TXT 与目录 |
| `/hosts` | 主机管理 | 连接设备、宿主列表、SDK 方言 |
| `/settings` | 设置 | 卡密、输入法、HeroSMS、代理池、拟人参数 |

## 3. 设备农场（`/devices`）

```
筛选：[宿主 ▾] [状态 ▾] [账号 ▾] [搜索____]        批量：[启动][停止][截图][更多▾]
┌────┬──────────────┬──────┬──────┬────────┬────────┬──────────┐
│ ☐  │ 设备          │ 坑位 │ 状态  │ 当前账号│ 最近运行│ 操作      │
├────┼──────────────┼──────┼──────┼────────┼────────┼──────────┤
│ ☐  │ xhs_01       │ 1    │ ●运行 │ @abc    │ 3m 前   │ ⋯        │
│ ☐  │ xhs_02       │ 2    │ ○停止 │ —       │ —       │ ⋯        │
└────┴──────────────┴──────┴──────┴────────┴────────┴──────────┘
```

- 主键是 `DeviceId`，展示名是 `containerName`；坑位与 ADB 端点放在详情里，不做行标识（见 ADR-0002）。
- 状态色：`running` 绿、`stopped` 灰、`unreachable` 黄、`deleted` 不显示（归档可查）。
- 200 行虚拟滚动；状态由事件推送增量更新，不做整表刷新。
- 行操作菜单对应旧 `SingleTaskDialog` 的 6 项：设代理 / 一键新机 / 改资料 / 关注 / 绑手机 / 抓 XML。

**设备详情抽屉**：基本信息、坑位占用历史、账号绑定、最近 20 条运行、截图预览。

## 4. 任务中心（`/tasks`）

| 区块 | 内容 |
|---|---|
| 运行中 | 设备 × 流程 × 步骤进度（第 N/M 步），可取消 |
| 待执行 | 队列、预计开始时间、被什么阻塞（坑位不足 / 设备离线） |
| 已完成 | 结果分布：成功 / 失败 / 需人工核对，可筛选、可导出 |
| 失败重试 | 只对 `retryable` 且**未过不可重试点**的运行开放 |

**运行详情（`/tasks/:id`）** 是核心可观测面：

```
时间线：step 01 打开主页 ✓ 1.2s
        step 02 进入发布页 ✓ 3.4s
        step 03 选图 6/9 ⚠ 2 次重试
        ...
        发布结果：待核对（基线 12 条 → 当前 12 条）
```
每一步展示：状态、耗时、重试次数、命中的定位器策略（`id/text/path/兜底`）、失败时的截图与 dump 链接。

## 5. 新建任务向导（`/tasks/new`）

三步式，对应旧项目 3 个对话框：

1. **选流程**：上号 / 发笔记 / 评论
2. **配参数**：只渲染该流程需要的字段（见下表）
3. **选设备**：设备树 + 坑位多容器勾选 + 预览「将执行 N 个任务」

| 流程 | 参数（来自旧控件） |
|---|---|
| 上号 | 登录源（5 种）、区号、批次大小/间隔、循环次数、失败重试次数、登录后动作开关（改资料/绑手机/关注/备份/清数据）、头像/昵称/代理来源 |
| 发笔记 | 发布模式（草稿/直接发）、9 列表格（导入 Excel / 在线编辑）、目标容器 |
| 评论 | 模式（指定笔记 / 指定评论点赞）、笔记 URL 表、主/子评论文案、评论间隔、评论模式、输入模式、分配模式、笔记点赞/收藏开关 |

旧项目「首次点开始任务只弹配置窗、要再点一次」的反模式取消。

## 6. 账号库（`/accounts`）

旧 `AccountImportDialog` 的 8 个子页在这里重组：

| 旧子页 | 新位置 |
|---|---|
| 账号（5 种登录方式） | 导入向导第 1 步：选登录方式 + 上传文件 |
| 头像 / 昵称 / 代理 | 素材库（`/assets`），账号只引用 |
| 魔云腾新机配置 | 导入向导第 2 步：是否随机新机 + 机型策略 |
| 关注账号 / 绑定账号 | 导入向导第 3 步：附加动作 |
| HeroSMS | 设置页的一个 Provider 卡片 |

账号列表列：账号标识、类型、状态（未登录/已登录/封禁/已废弃）、当前绑定设备、最近登录时间、使用次数。
N:M 绑定关系在详情里以时间线呈现（见 ADR-0002 关联决策）。

## 7. 设置（`/settings`）

| 分组 | 内容 |
|---|---|
| 授权 | 卡密、剩余天数、设备指纹 |
| 设备 | ADB 路径、ADBKeyboard、yadb、root 探测结果 |
| 扫码/接码 | HeroSMS（API Key、国家、价格上限、余额） |
| 代理 | 代理池导入、每机 IP 数、轮转策略 |
| 拟人 | HumanPolicy 全部参数（点击偏移、按压时长、打字节奏、思考停顿） |
| 运行 | 并发上限、每主机限流、重试策略、日志保留期 |
| 关于 | 版本、更新检查、日志目录 |

旧 `LLMConfigDialog` 不再存在（AI 功能作废）。

## 9. 设计约束

1. **一屏一职责**：不出现「标签页里套标签页」。
2. **表格优先**：200 台设备的操作靠表格 + 批量栏，不靠卡片墙。
3. **状态只从事件来**：UI 不自己维护真相，全部读投影（见 `docs/spec/shared-steps.md` §7）。
4. **失败可诊断**：任何失败都能一键看到截图、dump、命中的定位器与重试记录。
5. **不可重试的操作要二次确认**：发布、评论、绑手机、清数据。
6. **不引入 i18n**：面向国内客户，全中文（与 WDA 一致）。
