## 一句话

**界面本身不用任何品牌色**。主按钮接近黑；唯一的蓝色 `#1d5fbf` 只给屏幕上「当前正在做的事」；其余全用墨色和灰阶。

这个规则天然适配我们的画布：**只有正在执行的节点是蓝的**。

## 字体

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题 | 24 | 500 |
| 区块标题 | 16 | 500 |
| KPI 数字 | 30 | **500** |
| 正文 | 14 | 400 |
| 小字 / 标签 | 12 | 400 |

**两条硬规则**：
- **字重 700 只用于金额**，其他数字一律 400-500
- **等宽字体（Geist Mono）只用于 ID 和键名**，不用于普通数字

字体族：`Geist` → `Inter, system-ui, sans-serif`。

## 硬规则（违反即返工）

来自 23 个真实产品界面的测量，每条都有反例：

| 规则 | 说明 | 反例 |
|---|---|---|
| **彩色像素 < 1%** | 界面几乎无彩 | 品牌色主按钮、彩色 KPI 卡片 |
| **不要彩色图标圆底** | 图标不带底色圆 | 蓝色圆底 + 白色图标 |
| **卡片无阴影** | 靠 1px 线或一档色差分隔 | `box-shadow` |
| **不要入场大标题** | 没有 hero header | 40px 的「欢迎回来」 |
| **导航退到背景** | 选中项是中性灰胶囊或文字变色 | 彩色左边条 |
| **表格只有横线和对齐** | 无斑马纹、无表头色块、数字右对齐 | 交替行底色 |
| **零就是零** | 空值显示灰色横线 `—`，不显示 0 或空白 | 用 `-` 表示 0 |

## 画布交互（无限画布）

**实测数据**：现有三张图的纵向跨度都是 2400px、横向最多 400px，加上节点自身尺寸后需要
**2600px 高 × 738px 宽**。屏幕可视区约 800×900，不缩放只能看到 1/3。

所以画布必须是**真·无限画布**，不只是可滚动。

| 能力 | 规格 |
|---|---|
| **平移** | 拖拽空白区；滚轮纵向平移，Shift+滚轮横向 |
| **缩放** | 25% – 150%，默认 100%；滚轮 + Ctrl 缩放；左下角控件显示百分比 |
| **自适应全图** | 一键 fit：按所有节点包围盒算缩放比，留 48px 内边距，居中 |
| **缩略图** | 右下角，120×80，显示全图轮廓 + 当前视口框；点击跳转 |
| **网格** | **无点阵**（方向 A 的硬规则）；缩放到 <50% 时显示浅灰底色区分画布边界 |
| **坐标** | 节点 `position` 即画布坐标；拖拽后写回 JSON |
| **吸附** | 拖动时对齐到 8px 网格；靠近其它节点中线时显示 1px 对齐线 |

### 缩放级别下的可读性

| 缩放 | 显示什么 |
|---|---|
| ≥ 75% | 完整节点：类型图标 + 标题 + 指标行 |
| 50%–75% | 类型图标 + 标题，隐藏指标 |
| 25%–50% | 只显示节点色块 + 标题（截断） |
| < 25% | 只显示色块，不可编辑 |

**不做**：不做 3D、不做节点自由旋转、不做多层画布。

### 与方向 A 的关系

无限画布不违反「无彩账簿」的规则——画布本身仍是灰阶，**只有当前执行的节点是蓝的**。
缩放控件、缩略图都是白色小控件钉在角落，不带填充色。

# 节点与端口（flowgram 改造）

实施时按 `bytedance/flowgram.ai` 的 demo 完整改造，节点类型与端口如下。

## 五种节点

| 类型 id | 中文名 | 出口端口 | 说明 |
|---|---|---|---|
| `start` | 开始 | `out` | 流程入口，只能一个，不可删 |
| `mt-action` | 动作 | `success` / `failure` / `mismatch` | 在手机上做一件事；三个出口都在右侧，从上到下 |
| `mt-condition` | 条件 | `true` / `false` | 先判断，再决定走哪条路 |
| `mt-loop` | 循环 | `done` | **容器式**：循环体画在框内（`isContainer` + blocks） |
| `end` | 结束 | — | 流程结束，不可删 |

## 端口的中文释义（悬浮提示）

| 端口 | 释义 |
|---|---|
| `success` | 动作成功时走这条线 |
| `failure` | 没找到目标或校验不过时走这条线 |
| `mismatch` | 当前页面不是期望的页面时走这条线 |
| `true` | 条件成立时走这条线 |
| `false` | 条件不成立时走这条线 |
| `done` | 循环结束，继续往下 |

## 节点表单（中文标签）

**动作节点**：

| 标签 | 数据路径 | 说明 |
|---|---|---|
| 找什么 | `locate.intent` | 界面上能看到的文字，AI 按这段文字找目标 |
| 做什么 | `act.kind` | 点击 / 输入文字 / 滑动 / 按返回键 / 打开链接 / 等待 / 自定义动作 |
| 输入内容 | `act.text` | 可直接写文字，也可写流程参数名（运行时取参数值） |

**条件节点**：

| 标签 | 数据路径 | 说明 |
|---|---|---|
| 判断方式 | `judge.kind` | 页面是 / 元素存在 / 参数非空 |
| 页面 / 参数 | `judge.value` | 页面 id 或参数名 |

**循环节点**：

| 标签 | 数据路径 | 说明 |
|---|---|---|
| 最多重复几次 | `loopFor.max` | 1-100 |

## 一个实现坑（必记）

`FormItem` 的 `name` 属性是**显示标签**，不是数据路径：

```tsx
<FormItem name="找什么">              {/* name 就是显示的中文标签 */}
  <Field<string> name="locate.intent">  {/* 数据路径在 Field 上 */}
```

写错会直接显示成 `locate.intent`。

另外 Semi UI 的 `Select` **不接受 `title` 属性**，悬浮说明要放 `FormItem description`。
